==========================================================================
 VM 이 꺼져 있을 때 — 처음부터 다시 켜는 절차
==========================================================================

 [중요] VM 이 꺼져 있으면 SSH 가 붙지 않습니다.
        포트 포워딩(2222)은 "켜져 있는 VM" 으로만 연결해 주기 때문입니다.
        그래서 반드시 VM 을 먼저 켜야 합니다.


 ┌──────────────────────────────────────────────────────────────────────┐
 │ 명령을 "어디에" 치는지 구분하세요. 이걸 헷갈리면 전부 에러납니다.    │
 │                                                                      │
 │   0단계        내 PC (Windows)   ← VirtualBox 창 / CMD               │
 │   1단계        내 PC (Windows)   ← CMD 에서 ssh 실행                 │
 │   2~3단계      VM 안 (Ubuntu)    ← ssh 접속에 성공한 뒤              │
 │                                                                      │
 │ 프롬프트로 구분됩니다:                                               │
 │   C:\Users\for>              ← 내 PC (Windows CMD)                   │
 │   vboxuser@ubuntu:~$         ← VM 안 (Ubuntu)                        │
 │                                                                      │
 │ cd ~/Liinux- 같은 명령은 VM 안에서만 됩니다.                         │
 │ Windows CMD 에 치면 "지정된 경로를 찾을 수 없습니다" 가 납니다.      │
 └──────────────────────────────────────────────────────────────────────┘


--------------------------------------------------------------------------
 0단계  VM 켜기   ← 내 PC 에서 (SSH 아님!)
--------------------------------------------------------------------------

  VirtualBox 창을 열고 해당 VM 을 선택 → [시작] (초록 화살표) 클릭

  로그인 화면이 뜨고 30초쯤 지나면 SSH 가 준비됩니다.
  콘솔 창에서 로그인할 필요는 없습니다. 켜두기만 하면 됩니다.

  ※ 나중에 창을 닫을 때 "머신 전원 끄기" 를 고르면 VM 이 꺼져서
     웹 서비스도 같이 내려갑니다. 계속 서비스하려면 창을 그냥 두세요.

  [VirtualBox 창을 못 찾겠다면 — CMD 로 켜기]

    아래를 CMD 에 그대로 복사해서 붙여넣으세요.

      "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" list vms

    등록된 VM 이름이 따옴표 안에 나옵니다. 예: "Ubuntu"
    그 이름을 아래 명령의 Ubuntu 자리에 넣어 실행합니다.

      "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" startvm "Ubuntu"

    ※ 맨 앞의 & 기호는 쓰지 마세요. 그건 PowerShell 문법이라
       CMD 에서는 에러가 납니다. CMD 에서는 따옴표로 시작합니다.


--------------------------------------------------------------------------
 1단계  SSH 접속   ← 내 PC 의 CMD 또는 PowerShell
--------------------------------------------------------------------------

  VM 을 켠 뒤 30초 정도 기다렸다가 실행하세요.

  ssh -p 2222 vboxuser@127.0.0.1

  · 처음 접속 시 "Are you sure you want to continue connecting?" → yes
  · 비밀번호는 VM 로그인 비밀번호 (입력해도 화면에 안 보이는 게 정상)

  성공하면 프롬프트가 이렇게 바뀝니다:

      vboxuser@ubuntu:~$

  이제부터 치는 명령은 전부 VM 안에서 실행됩니다.

  [Connection refused 가 나온다면]
    거의 대부분 VM 이 아직 안 켜졌거나 부팅 중입니다.
      1) 0단계를 했는지 확인 (VirtualBox 에서 VM 이 "실행 중" 인지)
      2) 켰다면 30초 더 기다렸다가 재시도
      3) -p 2222 를 빼먹지 않았는지 확인
         (빼면 VM 이 아니라 내 PC 자신에 접속하려고 합니다)


--------------------------------------------------------------------------
 2단계  자기복구 설치   ← VM 안에서 (1회만 하면 됨)
--------------------------------------------------------------------------

  ★ 프롬프트가 vboxuser@ubuntu:~$ 인지 먼저 확인하세요.
    C:\Users\for> 상태라면 아직 1단계가 안 된 것입니다.

  cd ~/Liinux-
  git pull
  sudo ./scripts/setup_autoheal.sh

  · 비밀번호를 물으면 VM 로그인 비밀번호 입력
  · 설치는 한 번만 하면 됩니다. 이후 재부팅해도 유지됩니다.

  ※ 폴더 이름은 대문자 L 로 시작하는 Liinux- 입니다.
     리눅스는 대소문자를 구분하므로 liinux- 로 치면 못 찾습니다.
     헷갈리면 그냥 이렇게 하세요:

         cd ~
         ls
         (표시된 폴더 이름을 확인한 뒤)
         cd Liinux-


--------------------------------------------------------------------------
 3단계  확인
--------------------------------------------------------------------------

  journalctl -u vmlab-autoheal -n 30 --no-pager
  cat /var/lib/vmlab/tunnel_url

  두 번째 명령이 출력하는 주소가 새 외부 접속 주소입니다.

  ※ Quick Tunnel 은 재기동할 때마다 주소가 바뀝니다.
     고정 주소가 필요하면 도메인을 연결해 Named Tunnel 로 바꾸면 되고,
     그때도 앱이나 배포 구조는 바꿀 필요가 없습니다.


==========================================================================
 VM 을 켜면 자동으로 돌아오는 것 / 아닌 것
==========================================================================

  [자동]   db / web / nginx 컨테이너      restart: unless-stopped
  [자동]   GitHub Actions 러너            systemd 서비스
  [자동]   대기 중이던 배포(queued)       러너가 뜨면 가져감

  [수동]   Quick Tunnel (외부 주소)       ← 지금까지 손이 갔던 지점
           └ profile 밖에 있어서 일반 재기동으로는 안 살아납니다.

  2단계(자기복구 설치)를 하는 이유가 바로 마지막 항목입니다.
  설치 후에는 부팅 90초 뒤 자동으로 복구되고,
  이후 재부팅이든 터널 끊김이든 사람 손이 필요 없습니다.

  자기복구를 설치하기 전에 급히 터널만 켜려면:

      ./scripts/setup_tunnel.sh --quick


==========================================================================
 참고 1 — 창 없이 켜기 (선택)
==========================================================================

  콘솔 창이 거슬리면 백그라운드로 켤 수 있습니다.

  ★ CMD 와 PowerShell 의 문법이 다릅니다. 섞어 쓰면 에러납니다.

  [CMD 에서]  ← 따옴표로 바로 시작

    "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" list vms
    "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" startvm "Ubuntu" --type headless
    "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" controlvm "Ubuntu" acpipowerbutton

  [PowerShell 에서]  ← 맨 앞에 & 를 붙임

    & "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" list vms
    & "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" startvm "Ubuntu" --type headless
    & "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" controlvm "Ubuntu" acpipowerbutton

  ※ "Ubuntu" 자리에는 list vms 로 확인한 실제 VM 이름을 넣으세요.
  ※ headless 로 켜면 창이 안 뜹니다. SSH 로만 접속하게 됩니다.
     처음이라면 창이 뜨는 일반 모드(--type headless 없이)를 권합니다.
     부팅되는 걸 눈으로 볼 수 있어서 문제 파악이 쉽습니다.


==========================================================================
 참고 2 — 자주 쓰는 확인 명령 (VM 안에서)
==========================================================================

  # 컨테이너 상태   ★ -p vmlab 을 꼭 붙일 것
  sudo docker compose -p vmlab ps

  # 앱이 살아있는지 (VM 내부)
  curl -s localhost:8080/healthz

  # 현재 외부 공개 주소
  ./scripts/setup_tunnel.sh --status

  # 자기복구 동작 로그 (실시간, 빠져나올 때 Ctrl+C)
  journalctl -u vmlab-autoheal -f

  # 자기복구가 무엇을 할지 미리보기 (실제로는 아무것도 안 바꿈)
  sudo /usr/local/bin/vmlab-autoheal --dry-run


  [주의] docker compose 를 직접 쓸 때는 반드시 -p vmlab 을 붙이세요.
         안 붙이면 compose 가 디렉터리 이름에서 프로젝트명을 유추해서
         (liinux-) 실행 중인 스택을 못 보고,
         "Conflict. The container name /vmlab-db is already in use"
         오류가 납니다.


==========================================================================
 참고 3 — 문제가 생겼을 때
==========================================================================

  [VM 시작 자체가 실패 — "The VM session was aborted"]
  [결과 코드: E_FAIL (0x80004005)]

      원인은 거의 항상 하나입니다.
      Windows 의 Hyper-V 계열 기능이 CPU 가상화 기능을 먼저 차지해서
      VirtualBox 가 쓰지 못하는 상태입니다.
      (한 PC 에서 두 하이퍼바이저가 동시에 CPU 가상화를 쓸 수 없습니다)

      ---- 1) 먼저 확인 : 관리자 권한 CMD 에서 ----

        systeminfo

      맨 아래 "Hyper-V 요구 사항" 항목을 봅니다.
        · "하이퍼바이저가 검색되었습니다..." 라고 나오면 → 원인 확정
        · 요구사항이 모두 "예" 로 나오면 → 정상 (다른 원인)

      ---- 2) 해결 : 관리자 권한 CMD 에서 아래를 순서대로 ----

        ※ [Windows 키] → "cmd" 입력 → 마우스 우클릭
          → "관리자 권한으로 실행" 을 꼭 해야 합니다.

        bcdedit /set hypervisorlaunchtype off

        DISM /Online /Disable-Feature:Microsoft-Hyper-V-All /NoRestart
        DISM /Online /Disable-Feature:HypervisorPlatform /NoRestart
        DISM /Online /Disable-Feature:VirtualMachinePlatform /NoRestart

        ※ 위 3개 중 "기능을 찾을 수 없습니다" 가 나오는 것은
          원래 꺼져 있다는 뜻이니 무시하고 다음 줄로 넘어가세요.

      ---- 3) "코어 격리 - 메모리 무결성" 끄기 ----

        Windows 보안 → 장치 보안 → 코어 격리 세부 정보
        → "메모리 무결성" 을 [끔] 으로

      ---- 4) 반드시 재부팅 ----

        재부팅해야 적용됩니다. 재부팅 후 VM 을 다시 시작하세요.

      ---- 그래도 안 되면 ----

        · WSL2 / Docker Desktop / Windows 샌드박스 를 설치했다면
          그것들이 Hyper-V 를 다시 켭니다. 잠시 제거하거나 중지하세요.
        · BIOS/UEFI 에서 가상화가 꺼져 있을 수도 있습니다.
          (Intel VT-x / AMD SVM → Enabled)
        · 자세한 오류 원인은 로그에 남습니다:
            C:\Users\<사용자명>\VirtualBox VMs\testVM\Logs\VBox.log
          에서 "VERR_" 로 시작하는 줄을 찾으면 원인이 보입니다.


  [SSH 가 Connection refused]
      → 거의 100% VM 이 꺼져 있거나 아직 부팅 중입니다.
      → 0단계부터 다시. VirtualBox 에서 VM 상태가 "실행 중" 인지 확인.
      → 방금 켰다면 30초 기다렸다 재시도.
      → 켜져 있는데도 안 되면 VM 콘솔 창에서:
            sudo systemctl status ssh

  ["지정된 경로를 찾을 수 없습니다" (cd ~/Liinux- 실행 시)]
      → Windows CMD 에서 리눅스 명령을 친 것입니다.
        cd ~/Liinux- 는 SSH 접속에 성공한 뒤 VM 안에서만 됩니다.
      → 프롬프트를 확인하세요:
            C:\Users\for>          ← 여기선 안 됨 (내 PC)
            vboxuser@ubuntu:~$     ← 여기서 해야 함 (VM 안)

  ['&'은(는) 이 시점에 예상되지 않았습니다 (CMD)]
      → & 는 PowerShell 문법입니다. CMD 에서는 빼고
        따옴표로 바로 시작하세요.

  [배포가 queued 에서 안 움직임]
      → VM 이 꺼져 있거나 러너가 죽어 있습니다.
      → VM 안에서:  systemctl status actions.runner.*

  [웹은 뜨는데 외부 주소가 안 열림]
      → 터널이 끊긴 것입니다. 이것이 자기복구를 만든 이유입니다.
      → 임시 조치:  ./scripts/setup_tunnel.sh --quick

  [로그인이 안 됨 (비밀번호는 맞는데)]
      → http:// 로 접속했기 때문입니다.
         SESSION_COOKIE_SECURE=true 라서 브라우저가 쿠키를 안 보냅니다.
         반드시 https:// 터널 주소로 접속하세요.


==========================================================================
 안전 수칙 — 취약(vulnerable) 모드 실습 전
==========================================================================

  취약 빌드는 절대 외부에 노출하면 안 됩니다.
  실습 전에 반드시 터널을 내리세요:

      ./scripts/setup_tunnel.sh --down

  ※ --down 은 터널 컨테이너를 삭제하므로, 자기복구가 이를
     "사용자가 의도적으로 내렸다" 로 판단해 다시 켜지 않습니다.
     또한 SECURITY_MODE=vulnerable 이면 자기복구가 오히려
     외부 노출을 차단합니다. 이중으로 안전합니다.
