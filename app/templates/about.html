아키텍처 및 데이터 흐름

이 페이지는 포트폴리오 방문자(면접관 포함)가 시스템 구성을 한눈에 파악하도록 만든 설명 페이지입니다.

1. 배포 파이프라인

개발 PC                GitHub                    로컬 VM (Ubuntu 24.04)
  │                      │                              │
  │  git push main       │                              │
  ├─────────────────────▶│                              │
  │                      │  ① CI: lint·보안스캔·테스트    │
  │                      │                              │
  │                      │  ② self-hosted runner 가      │
  │                      │     작업을 가져감 (pull)       │
  │                      │◀─────────────────────────────┤
  │                      │                              │
  │                      │  ③ docker compose up --build │
  │                      │  ④ DB 마이그레이션 적용        │
  │                      │  ⑤ /healthz 검증              │
  │                      │  ⑥ 실패 시 이전 이미지 롤백    │

VM 이 NAT 뒤에 있어 GitHub 가 VM 으로 접속할 수 없으므로, VM 안의 러너가 GitHub 에 주기적으로 물어보는 pull 방식을 사용합니다. 공유기 포트를 열지 않아도 배포가 됩니다.

2. 요청 처리 흐름 (데이터 흐름)

[외부 사용자]
     │  HTTPS
     ▼
[Cloudflare Tunnel]  ← VM 이 바깥으로 연결 (인바운드 포트 개방 없음)
     │
     ▼
[Nginx]  리버스프록시 · 정적파일 · 요청 크기 제한 · 레이트리밋
     │  proxy_pass (X-Forwarded-For / X-Real-IP 전달)
     ▼
[Gunicorn]  WSGI · 워커 프로세스 관리
     │
     ▼
[Flask 애플리케이션]
     │  ① before_request  : 클라이언트 IP 판별, 타이머 시작
     │  ② CSRF 검증        : 상태 변경 요청 토큰 확인
     │  ③ 라우팅 · 입력검증 · 권한확인
     │  ④ DB 접근          : 파라미터 바인딩 쿼리
     │  ⑤ 템플릿 렌더링    : 자동 이스케이프
     │  ⑥ after_request   : 보안 헤더 부착
     │  ⑦ 접속 로그 적재   : 위협 패턴 분석 후 비동기 기록
     ▼
[MariaDB]  게시판 데이터 + 접속 로그 + 보안 이벤트
     │
     ▼
[관리자 대시보드]  로그 집계 · 공격 탐지 · IP 분석

3. 접속 로그 수집 구조

모든 요청은 응답 직후 after_request 훅에서 분석됩니다. URL 인코딩을 2단계까지 해제한 뒤 SQL Injection·XSS·경로탐색·명령주입 등 패턴을 검사해 위협 점수(0~100)와 태그를 산출합니다.

  • 비동기 적재: 큐 + 백그라운드 스레드로 배치 INSERT — 응답 지연 없음
  • 민감정보 마스킹: 비밀번호·토큰 파라미터는 값을 저장하지 않음
  • 장애 격리: 로그 적재가 실패해도 서비스는 정상 동작
  • 보존 기간: 기본 90일 후 삭제 (IP 는 개인정보로 취급)

4. 이중 모드 설계

환경변수 SECURITY_MODE 하나로 동일 코드베이스가 두 얼굴을 가집니다. 이것이 "취약점 → 방어" Before/After 를 증명하는 장치입니다.

구분vulnerablesecure (기본값)
SQL 쿼리문자열 조립파라미터 바인딩
출력 처리이스케이프 없음자동 이스케이프 + CSP
CSRF검증 없음토큰 검증
객체 접근소유권 미확인소유권·역할 확인
업로드검증 없음확장자·매직바이트 3중 검증
로그인시도 제한 없음브루트포스 차단 + 타이밍 방어
보안 헤더없음CSP·HSTS·X-Frame-Options 등
네트워크격리 (외부 차단)터널로 외부 공개 가능

주의: vulnerable 모드는 절대 인터넷에 노출하지 않습니다. 호스트 전용 네트워크에서 Kali VM 으로만 접근합니다.
